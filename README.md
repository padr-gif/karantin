# Карантин

Мобильная зомби-выживалка в духе Project Zomboid. Работает в браузере, на выходе один HTML-файл: его можно открыть на телефоне, выложить на сайт или завернуть в приложение.

## Быстрый старт

Нужен [Node.js](https://nodejs.org) 18 или новее.

```bash
npm install        # один раз, ставит Playwright для тестов
npm run dev        # игра на http://localhost:5173, пересобирается при каждом сохранении файла
npm run build      # релиз: dist/karantin.html
npm test           # автотесты в headless-браузере
```

С телефона в той же Wi-Fi сети открой `http://<IP компьютера>:5173`.

Для тестов браузер Playwright ставится командой `npx playwright install chromium`.

## Устройство проекта

```
src/index.html        разметка: меню, HUD, экраны, панели
src/styles.css        все стили
src/js/*.js           код игры, по порядку номеров
assets/sprites/*.png  листы спрайтов (персонажи, зомби, мебель, иконки)
assets/atlas.json     координаты кадров на листах
assets/icons.json     координаты иконок предметов
tools/icons/gen.py    генератор пиксельных иконок (Python + Pillow)
tools/mh3d/           персонажи из модели MakeHuman (CC0): рендер, позы, анимации, запекание листов
tools/webp.py         WebP-копии листов для сайта (assets/sprites/webp/, пересоздаются при сборке сайта сами)
tests/run.mjs         автотесты
build.mjs, serve.mjs  сборка и сервер для разработки
```

Файлы из `src/js` склеиваются по порядку номеров в одну функцию и видят переменные и функции друг друга. Поэтому порядок важен: файл может пользоваться тем, что объявлено в файлах с меньшим номером.

Базовые файлы `00`–`22`: данные, карта, обновление мира, отрисовка, интерфейс, звук. Дальше — механики по темам (`23-survival-kit` … `73-stability`): одежда, раны, погода, мебель, районы и так далее.

### Правило: не накладывать код на код

Функцию объявляют **один раз** (`function name() {…}`) и больше нигде не переписывают. Так нельзя:

```js
const useItem23 = useItem;            // ✗ подмена: старая версия прячется внутри новой,
useItem = function (id, idx) { … };   //   и через пару таких слоёв никто не знает, что на самом деле выполняется
```

Если механике нужно что-то поменять в существующей функции, есть два пути:

1. **Дописать прямо в функцию** — когда это часть её работы (новый вид урона в `dmgK`, новая строка в `moodleList`).
2. **Подключиться через точку расширения** (`src/js/01-hooks.js`) — когда механика своя, отдельная:

| что нужно | как |
|---|---|
| что-то делать каждый кадр | `onUpdate(dt => { … })` |
| сохранить/загрузить свои данные | `onSave(d => { d.my = … })`, `onLoad(d => { … })` |
| настроить новую игру / новый мир | `onStartNew(() => { … })`, `onNewWorld(o => { … })` |
| дописать что-то в окно (вкладку, блок) | `onPanel(() => { … })` |
| своё действие у предмета мира | `addActions(out => out.push({kind:'my', label:'…', f}))` и `defAction('my', {name, icon, run})` |
| особое применение вещи из рюкзака | `defUse((it, d) => it.id === 'my', (it, k, d) => { … })` |

Порядок вызова — порядок файлов. У `onUpdate`, `onLoad`, `onStartNew`, `onNewWorld`, `onPanel` есть второй аргумент `pre` — он выполняется *до* основного шага, а то, что он вернул, приходит в `post` вторым параметром: `onUpdate((dt, x) => …, dt => x)` (подробнее — в комментариях `01-hooks.js`).

### Проверка, что ничего не сломалось

```bash
node build.mjs --dev && node tests/golden.mjs   # эталонная игра: «Эталон совпал» — поведение не изменилось
node tests/run.mjs                              # все автотесты
```

`tests/golden.mjs` проигрывает заскриптованную игру с фиксированной случайностью (драка, дом, обыск, ремесло, ночь, сохранение, переход в соседний район) и сравнивает состояние и картинку с `tests/golden.json`. Для чистки кода эталон должен совпадать; если поведение меняется намеренно — записать новый: `node tests/golden.mjs save`.

Файл `99-wiring.js` подключает кнопки и запускает игру, он всегда последний.

## Как добавить предмет

1. Описать его в новом или подходящем файле:
   ```js
   Object.assign(ITEMS, {crowbar2:{name:'Монтировка', kind:'weapon', dmg:36, range:1.2, cd:.65, cleave:1, dur:80, verb:'Взять в руки'}});
   DESC.crowbar2 = 'Короткая монтировка. Прочная и удобная.';
   CONT.toolrack.loot.push('crowbar2');   // где найти
   ```
2. Нарисовать иконку в `tools/icons/gen.py` (функция с `@icon('crowbar2')`) и выполнить `npm run icons`.
3. `npm test`, затем проверить руками в `npm run dev`.

## Районы (бесконечный мир)

Конца у игры нет. Город — один район округа: родной городок 256×256 клеток, остальные районы 184×184. Через бетонные блоки на блокпосту можно перелезть, по трассе дойти до края карты и уйти в соседний район (`src/js/70-districts.js`).

В памяти всегда только один район, поэтому игра не тяжелеет со временем. Сид района считается из сида родного города и координат района. Покинутый район хранится как изменения (то же, что в сохранении: обысканное, двери, мертвецы…), сжатые LZW, примерно 10 КБ. Помним до 16 районов; забытый строится заново из сида. Типы районов (`src/js/71-terrain.js`): городок, деревня, лес с дачами, промзона, центр города. Родной район всегда городок, тип соседа выбирается из сида и удалённости: рядом чаще деревня и лес, дальше — промзона и центр. Чем дальше от дома и чем позже, тем больше мертвецов в новом районе (не больше 280 на район); пока тебя нет, в оставленный район забредают мертвецы и он ветшает.

## Округ в духе Project Zomboid (новые игры)

`src/js/74-county.js`, `world.gen = 3`: родной район и соседние городки, карта 256×256 (остальные районы и старые сохранения — 184×184, см. `setWorldSize` в `03-map.js`). Как Riverside: вдоль главной трассы с одной стороны течёт река, трасса-поперёк идёт по мосту. Город длинный и узкий: поперечные улицы с разным шагом, у каждого квартала свои задние улицы (поэтому они идут со сдвигом), ряд домов окнами на реку. В центре главной улицы — магазины, аптека, хозтовары, полиция, кафе и конторы, дальше — жилые кварталы и тупики-грунтовки с домом на отшибе. За городом: заправка и склады за забором у трасс, дома вдоль дороги, 2–4 фермы (дом, амбар, двор, пашня с урожаем, пастбище за изгородью, лесополоса), озеро с рыбацким домиком, охотничьи домики; к дальним фермам и домикам ведут грунтовки.

Грунт лежит отдельным слоем `soil` поверх травы (`03-map.js`): 1 — грунтовка, 2/3 — пашня с бороздами вдоль x / y. Для остальной игры клетка остаётся травой (шаги, снег, грядки), рисуется в `drawSoil`, на карте — `soilCol`. Генераторы не строят на грунте и не сажают на нём деревья (`rectFree`, `genFinish`).

## Активная зона

`ZONE_R` в `05-geometry.js`: поле путей мертвецов считается только в квадрате ±56 клеток вокруг героя, мертвецы дальше «спят» и раз в секунду дёшево сдвигаются (`farZombie` в `08-update.js`), туман войны пересчитывается окном вокруг героя (`updateFog`). Поэтому нагрузка почти не зависит от размера карты, а мертвецов на большой карте столько же на клетку, сколько на старой.

## Города и дворы

`src/js/72-city.js` (`world.gen = 2`, теперь только центр города; сохранения gen 2 строят и городок этим генератором): городок и центр строятся неровной сеткой — свой шаг улиц по каждой оси, часть улиц обрывается на перекрёстке, в больших кварталах бывают тупики-проезды с разворотом. Есть многоэтажки (`buildFlats`: коридор и квартиры по обе стороны), школа, дома пяти размеров. Дворы: заборы (штакетник, сетка, профлист), гаражи с подъездом и машиной, огороды (выкопать овощи) и яблони. Работает при `world.gen >= 2`; новая игра ставит `world.gen = 3`. Старые сохранения строятся тем генератором, которым были созданы, чтобы мебель и двери совпали по номерам.

## Сохранения

С версии 0.54 (`src/js/73-stability.js`) тело сохранения сжато (LZW, в 5–6 раз меньше), у каждого слота есть запасная копия — прошлое удачное сохранение; если основное не читается, грузится она. В окне «Загрузить» сохранение можно выгрузить в файл `.karantin` и загрузить из файла. В паузе — «Отчёт об ошибках» (журнал ошибок + результат теста скорости), в настройках — «Тест скорости» (только из главного меню).


Сохранения игроков лежат в браузере (и в облаке, если игра открыта как артефакт Claude). Формат описан в `serialize` и `applySave` (файлы `19-saves.js`, `42`, `43`). Новые поля добавляй так, чтобы старые сохранения тоже загружались: проверяй, что поле может отсутствовать.

## Админ-меню

`src/js/75-admin.js`. Включается в настройках («Админ-меню»), открывается кнопкой «Админ» на нижней панели или клавишей ` (Ё). Вкладки: «Герой» — бессмертие, вылечить, накормить; «Вещи» — наборы и поиск любой вещи; «Мир» — убрать или призвать мертвецов, время суток, дождь, открыть карту, телепорт тапом по карте.

## Игра на телефоне (PWA)

Игра опубликована как сайт-приложение: **https://padr-gif.github.io/karantin/**

Открой ссылку в Chrome на Android и выбери «Установить приложение» или «Добавить на главный экран». На iPhone в Safari: «Поделиться» → «На экран „Домой“». Игра откроется во весь экран и будет работать без интернета.

```bash
npm run site      # собрать сайт в site/ (страница, манифест, service worker, иконки)
npm run deploy    # собрать и опубликовать в ветку gh-pages
npm run appicon   # перерисовать иконку приложения (tools/icons/appicon.py)
```

## Шрифты

Oswald, PT Sans и PT Mono лежат в `assets/fonts` (лицензия SIL OFL, файлы `OFL-*.txt`) и вшиваются в страницу при сборке. Внешних запросов к Google Fonts нет: если их сервер недоступен, игра всё равно запускается.

## Персонажи

Игрок и зомби — 3D-модель человека MakeHuman (CC0), отрендеренная в спрайты. Анимации задаются в `tools/mh3d/anims.py`,
внешность листов — в `tools/mh3d/looks.py`. Пересобрать листы и атлас (несколько минут):

```bash
python3 tools/mh3d/bake.py          # все: pm pf zm zf zh
python3 tools/mh3d/bake.py zm       # только зомби-мужчин
```

Кадр хранит номер цвета (кожа, волосы, одежда…) в красном канале и яркость в синем, игра перекрашивает его под внешность.
