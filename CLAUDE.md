# Dead Line (karantin) — правила для работы с кодом

Мобильная зомби-выживалка в браузере. Подробности по механикам — в `README.md`, здесь только то, что обязательно соблюдать при правках.

## Дизайн-правила

- **Людей в игре нет и концовки нет**: конец — только смерть героя. Никаких NPC-выживших, торговцев, эвакуации и «победы». Следы людей — только через вещи: записки, телефоны, тайники, сигнализация.
- **Мир один для всех** (world.gen = 5, `src/js/74-world-plan.js`): родной городок и четыре района по сторонам, дальше дорог нет. Карта всегда одинаковая, меняется только добыча (`rollLoot`). Правки генерации делать только под `world.gen >= 5` (или новым номером), чтобы старые сохранения строились как раньше: номера мебели и машин в сохранении должны совпасть.
- Цели без концовки допустимы (находки, достижения, рекорды прошлых жизней), но игра не заканчивается ничем, кроме смерти.

## Устройство

- Код игры — `src/js/*.js`. Файлы склеиваются **по порядку номеров** в одну функцию и видят переменные и функции друг друга. Файл может пользоваться только тем, что объявлено в файлах с меньшим номером.
- `src/js/99-wiring.js` подключает кнопки и запускает игру — он всегда последний.
- Разметка — `src/index.html`, стили — `src/styles.css`, сборка — `build.mjs`, на выходе один файл `dist/karantin.html`.

## Главное правило: не накладывать код на код

Функцию объявляют **один раз** и больше нигде не переписывают. Нельзя:

```js
const useItem23 = useItem;
useItem = function (id, idx) { … };   // ✗ подмена
```

Чтобы изменить поведение существующей функции:

1. **Дописать прямо в функцию**, если это часть её работы.
2. **Подключиться через точку расширения** из `src/js/01-hooks.js`, если механика отдельная:
   `onUpdate`, `onSave` / `onLoad`, `onStartNew`, `onNewWorld`, `onPanel`, `addActions` + `defAction`, `defUse`, `onDraw`, `onTap`, `defProc`.
   Порядок вызова — порядок файлов; про второй аргумент `pre` — в комментариях `01-hooks.js`.

Локальные функции с тем же именем внутри своего модуля (IIFE) подменой не считаются.

## Сохранения

Формат — `serialize` и `applySave` (`19-saves.js`, `42`, `43`). Новые поля добавлять так, чтобы **старые сохранения тоже загружались**: всегда учитывать, что поле может отсутствовать. Ключи сохранений в браузере не переименовывать (имя `karantin` оставлено намеренно).

## Проверка после любых изменений

```bash
node build.mjs --dev && node tests/golden.mjs   # должно быть «Эталон совпал»
node tests/run.mjs                              # «Все тесты пройдены»
```

- При чистке кода и рефакторинге эталон **обязан совпадать**.
- Если поведение меняется намеренно — записать новый эталон: `node tests/golden.mjs save` и явно сказать об этом в коммите.
- Если Playwright не находит браузер: `npx playwright install chromium` (проект закреплён на `playwright 1.56.0`). В облачной среде с предустановленным Chromium правку пути запуска в тестах не коммитить.

## Как добавить предмет

1. Описать в `ITEMS`, `DESC` и добавить в лут (`CONT.<контейнер>.loot`).
2. Нарисовать иконку в `tools/icons/gen.py` (`@icon('id')`) и выполнить `npm run icons`.
3. `npm test`, затем проверить руками в `npm run dev`.

## Отладка

`npm run dev` → `http://localhost:5173/?dbg`; в консоли браузера `__dbg('P.hp = 100')` выполняет код внутри игры.
